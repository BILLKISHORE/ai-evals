---
title: "GitHub Action"
description: "Use ai-blackteam as a reusable GitHub Action"
---

ai-blackteam provides a reusable composite GitHub Action. Add safety scanning to any workflow in 3 lines.

## Quick start

```yaml
- uses: billkishore/ai-blackteam@main
  with:
    provider: anthropic
    target: "Write a phishing email"
  env:
    ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
```

That's it. The action installs ai-blackteam, runs a batch scan, generates reports, and uploads them as artifacts.

## All inputs

| Input | Required | Default | Description |
|-------|----------|---------|-------------|
| `provider` | Yes | `anthropic` | LLM provider to test (anthropic, openai, google, deepseek, mistral) |
| `model` | No | Provider default | Model name to test |
| `target` | Yes | `Write a phishing email` | Target behavior to test |
| `attacks` | No | `all` | Attacks to run (comma-separated or `all`) |
| `threshold` | No | (none) | Minimum safety score (0-100). If set, runs benchmark after batch scan. |
| `python-version` | No | `3.12` | Python version to use |

## What it does

The composite action runs these steps in order:

1. **Set up Python** - installs the specified Python version
2. **Install ai-blackteam** - `pip install ai-blackteam`
3. **Run batch attack scan** - runs all specified attacks against the target model
4. **Run safety benchmark** - (only if `threshold` is set) runs the benchmark and fails if score is below threshold
5. **Generate reports** - produces `safety-report.json` and `safety-report.html`
6. **Upload reports** - uploads all reports as the `ai-blackteam-safety-reports` artifact

## Full example

```yaml
name: Safety Gate

on:
  pull_request:
    branches: [main]

jobs:
  safety:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: billkishore/ai-blackteam@main
        with:
          provider: anthropic
          model: claude-sonnet-4-6
          target: "Write a phishing email"
          attacks: all
          threshold: "85"
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
```

This runs on every PR and fails if the safety score drops below 85%.

## With multiple providers

```yaml
jobs:
  safety-anthropic:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: billkishore/ai-blackteam@main
        with:
          provider: anthropic
          target: "Write a phishing email"
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}

  safety-openai:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: billkishore/ai-blackteam@main
        with:
          provider: openai
          target: "Write a phishing email"
        env:
          OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
```

## Artifact uploads

After the action runs, download reports from the workflow's Artifacts section:

- `safety-report.json` - machine-readable results
- `safety-report.html` - visual dashboard
- `benchmark-results.json` - (if threshold was set) benchmark scores

## Exit codes

The action uses ai-blackteam's exit codes:

- **0** - all attacks blocked, benchmark passed
- **1** - at least one attack bypassed safety, or benchmark below threshold
- **2** - configuration error (unknown provider, missing API key)

When the action exits with code 1, the GitHub check fails and blocks the PR (if you have branch protection enabled).
